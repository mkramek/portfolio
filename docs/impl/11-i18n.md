# Impl 11: Internationalization

**Read first:** [[../arch/11-i18n|Internationalization]], [[../arch/adr/012-locale-prefixed-routing|ADR-012]], [[../arch/adr/013-sidecar-translation-table|ADR-013]], [[../arch/adr/014-isr-for-public-portfolio|ADR-014]]

## Goal

Route-based i18n (English default, additional locales admin-configurable) across the public portfolio, the admin panel, the generated CV, and JSON export/import — with no i18n runtime shipped to the browser and less per-request DB load on the public route than before this work started.

## Steps

1. **Locale foundation.** `Locale` + `Translation` models and a `TranslatableEntity` enum in `prisma/schema.prisma`; `CvSettings.locale`/`CvSnapshot.locale` (`String @default("en")`) in the same migration. `lib/i18n/config.ts` (the in-code `LOCALE_CATALOGUE`), `lib/i18n/translatable.ts` (per-entity `FieldSpec[]`, reusing `lib/admin/fields.ts`'s type), `lib/i18n/localize.ts` (field-level merge), `lib/i18n/completeness.ts` + `lib/i18n/report.ts` (missing-field accounting). `getLocales()`/`setLocale()`/`getTranslationsForLocale()`/`setTranslation()`/`deleteTranslationsFor()` in `lib/content.ts`, following the existing `Theme`/`Section` merge-on-read pattern (ADR-007).

2. **Route restructure.** Move `app/app/{layout,page,coming-soon}.tsx` and the entire `app/app/admin/**` tree under `app/app/[lang]/`. Rewrite `app/proxy.ts` for the locale redirect + relocated `/admin/**` auth check (see [[../arch/11-i18n|arch doc]] for the exact matcher/branch shape). Add `app/global-not-found.tsx` + `experimental.globalNotFound` in `next.config.ts` (required once the root layout sits on a top-level dynamic segment — Next can't compose a single 404 page from `layout.js` + `not-found.js` otherwise).

3. **Dictionaries + public strings.** `lib/i18n/dictionaries/{en,pl}/{public,cv}.ts`, `lib/i18n/dictionary-loader.ts` + `lib/i18n/dictionaries.ts`, `lib/i18n/plural.ts` (`Intl.PluralRules`-based, for `"3 ROLES"` / `"3 ROLE"` pl). Thread dictionary props through `components/portfolio.tsx` → `hero.tsx`/`experience.tsx`/`case-study.tsx`/`ledger-row.tsx`, and `app/[lang]/coming-soon.tsx`.

4. **Localized content read path.** `lib/i18n/content.ts`'s `getLocalizedContent(locale)` — the same getters `components/portfolio.tsx` already called, plus one `Translation` query, merged via `localize.ts`.

5. **Admin chrome.** `lib/i18n/dictionaries/{en,pl}/admin.ts` (the large one — nav, tab headers, list configs, field overrides, every admin component's copy). `localizeFieldSpecs()`/`localizeListConfig()` in `lib/admin/fields.ts`. Every admin `page.tsx` resolves `getAdminDictionary()` server-side and passes plain, already-localized props to its client component — `EntityView`, `AppearanceView`, `CvBuilder`, `CvHistory`, `DataPanel`, `ProfilePanel`, `SectionsView`, `SetupWizard`, `LoginForm`, `PasskeySection`, `AdminNav`.

6. **Locales tab + Translations tab.** `/admin/locales` (`components/admin/locales-view.tsx`) — per-catalogue-locale enable toggle + completeness bar, `en` shown as a permanent, non-toggleable default. `/admin/translations` (`components/admin/translations-view.tsx`) — target-locale picker, "missing only" filter (both as URL search params, server-rendered), per-row side-by-side English/target editor built from `translatable.ts`'s field lists through the existing `FieldControl`. `PATCH /api/admin/locales`, `PUT /api/admin/translations/[entity]/[entityId]` (validated via `lib/i18n/translation-validation.ts`, a structural check rather than a full per-entity Zod schema — see that file's own comment for why). Translation cascade delete wired into `lib/admin/routes.ts`'s generic factory via an injected `deleteTranslations` callback per `RouteEntityConfig`.

7. **CV locale.** `lib/cv.ts`'s `resolveLiveCv(locale)` (merges translations for CV-relevant entities: profile, roles, projects, skillGroups, testimonials, education, languages, cvSettings itself). `createCvSnapshot`/`getCvSnapshotById`/`getCvSnapshotsWithVersions` carry `locale` through. `components/cv/cv-document.tsx` takes a `cvDict` prop (content locale) separate from its existing `locale` prop (admin-chrome locale, screen-only "back to builder" link). Language selector in `components/admin/cv-builder.tsx`, gated on more than one enabled locale existing.

8. **Export/import.** `translations`/`locales` added to `exportAll()`/`importAll()` (`lib/data.ts`) and `exportSchema` (`.default([])` for backward compatibility with pre-i18n backups). `Translation`/`Locale` added to `e2e/helpers/db.ts`'s `CONTENT_TABLES`.

9. **SEO.** `generateMetadata` in `app/[lang]/layout.tsx` (localized title/description, `alternates.canonical`/`languages`, OG/Twitter). `app/sitemap.ts` (one entry per enabled locale + hreflang alternates), `app/robots.ts`. `lib/seo.ts`'s `personJsonLd()`. `components/portfolio/language-switcher.tsx`. Fixed the pre-existing "coming soon" title leak (`Profile.name` was appearing in the pre-publish page's `<title>`, contradicting [[../arch/04-setup-publish-gate|the publish gate's own no-personalization rule]]) as part of the same `generateMetadata` work.

10. **Caching.** Dropped `force-dynamic` from `app/[lang]/layout.tsx`/`page.tsx`, added `revalidate = 300`. `lib/revalidate.ts`'s `revalidatePublicPortfolio()`, called from `lib/admin/routes.ts`'s generic factory and every other mutating admin route that touches public-facing state. `app/sitemap.ts` kept `force-dynamic` deliberately (see [[../arch/adr/014-isr-for-public-portfolio|ADR-014]]'s consequences) so `next build` stays database-independent.

## Done when

- `bun run build` succeeds with `DATABASE_URL` pointing at an unreachable host — confirms `generateStaticParams` was correctly *not* added anywhere on the public path, and that `app/sitemap.ts` correctly stays `force-dynamic` rather than attempting build-time prerendering.
- `/` 308-redirects to `/en`; `/pl` 404s while disabled, and starts rendering the moment it's enabled from `/en/admin/locales` — with no restart or redeploy.
- A translation entered in `/en/admin/translations` shows up on the corresponding `/pl` page immediately (revalidation), and an untranslated field on the same row still renders its English text (field-level fallback).
- `bun test` and `TEST_DATABASE_URL=… bun test` (`bun run test:db`) both pass — the latter exercises the DB-backed locale/translation/CV-locale round trips skipped by the former.
- A production build (`next build && next start`) serves a cached response on the second request to `/en` — confirmed via response time, not `Cache-Control` (App Router dynamic-segment pages set `no-store` client-side headers regardless of server-side ISR caching; the win is server-side).
